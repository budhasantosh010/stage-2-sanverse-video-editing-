# Deferred Ideas

Deferred does not mean rejected. Each idea has a trigger so it returns when evidence justifies it.

| Idea | Why deferred | Reconsider when |
|---|---|---|
| Complete Premiere/Resolve/After Effects feature parity | Too broad; obscures the non-editor outcome | Repeated real workflows cannot be expressed with the staged primitive set |
| Full auth, billing, tenancy, Kubernetes, and enterprise operations | Product value and load are not yet demonstrated | G8 local alpha meets user outcome gates and a real multi-user launch is planned |
| Microservices | Adds deployment and consistency cost | Modular monolith hits measured scaling or team-ownership limits |
| SAM2/advanced segmentation and tracking | Expensive and unnecessary for the first slice | Validated user edits require object-aware spatial persistence |
| Custom model training | No proprietary evaluation dataset yet | G8+ feedback data shows a repeatable gap and privacy/consent rules exist |
| Public API/MCP | Core contracts are not stable | G8 engine workflows are reliable and versionable |
| Semantic memory/indexing for project docs | Adds models, dependencies, latency, and hidden retrieval behavior | Lightweight committed continuity repeatedly fails in measured sessions |
| Automatic Mermaid rendering on every decision | Network/dependency cost for little current value | Decision graph becomes too large for Markdown/Mermaid source review |
| Heuristic automatic goal scoring | Risks false precision | Real metrics and calibrated thresholds exist |
| Decorative branding, gradients, and fancy motion | Does not improve the first user outcome | Core usability is proven and brand work becomes an explicit goal |
